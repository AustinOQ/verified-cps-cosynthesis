# Controller Fitting Sequence Artifact

This is a compact, self-contained artifact for the `architecture-fit` work. It
is intended to be branch/upload friendly: one runner, one bundled code/model
tree, one output directory, and one human-readable report that demonstrates the
sequence of simplified controller fitting/training methods developed in this
subproject.

The artifact uses local copies under `bundle/`. At the start of every run it
discovers SysML files containing a `#Neural` action, reads their package names,
controller inputs, controller outputs, completion condition, requirements,
scenario bounds, and process equations, and writes generated results to
`outputs/latest/`.

## Run

From this directory:

```bash
bash run_fitting_sequence.sh
```

This recursively reads `bundle/sysml-models/` and regenerates
`outputs/latest/`. To run particular files instead, list their paths:

```bash
bash run_fitting_sequence.sh path/to/first.sysml path/to/second.sysml
```

To discover files under another directory:

```bash
bash run_fitting_sequence.sh --models-root path/to/models
```

Each feedforward size is derived from the comparison boundaries and outputs in
that model's current SysML contents.

For a quick wiring check:

```bash
bash run_fitting_sequence.sh --smoke-training
```

## What It Demonstrates

The artifact asks whether a SysML model can be controlled by a simple
non-recurrent controller instead of a larger recurrent learner.

The sequence is:

```text
1. Affine/rule fit from NeuralRequirements
2. Memoryless controller check
3. Provable Markov/MDP controller check
4. Reduced feedforward training from the run-local certified specs
```

The checks are ordered from cheapest to strongest. The final stage trains small
non-recurrent policies from the certified architecture specs generated in the
same run.

## Plain Language

- A SysML `NeuralRequirement` is the part of the model that says which
  controller outputs are safe or required for the current observation.
- The affine/rule stage reads the requirement and checks whether a Boolean
  requirement determines exactly one action for the current observation.
- The memoryless stage asks whether the current controller inputs alone are
  enough for the current decision. This is useful when the goal is to remove a
  GRU or other recurrent learner.
- The Markov/MDP stage asks a stronger question. It checks whether the buffer is
  enough to make the next step of the modeled process determined. This stage
  generates proof obligations from the current SysML files. It calls Z3 during
  the run. It saves certificates, reduced specs, SMT-LIB queries, and proof or
  counterexample transcripts under `outputs/latest/03_markov_mdp/`.
- The reduced training stage reads the specs generated by the current run. It
  derives one feedforward size from each SysML requirement, trains
  that policy, and saves weights under
  `outputs/latest/04_reduced_training/`.
- The safety check is rebuilt from the current SysML requirement.

The reported safety violation rate counts executed controller actions that do
not satisfy the current SysML `NeuralRequirement`. Task completion is reported
separately as the success rate.

## What Gets Fitted

| stage | what the checker does | fitting status in this artifact |
|---|---|---|
| Affine/rule fit | Checks whether the requirement directly gives one Boolean action. | This is extracted from the current SysML file and has `0` learned parameters. |
| Memoryless controller check | Checks whether the current controller inputs alone are enough for the current decision. | Produces current-input evidence for later feedforward fitting. |
| Provable Markov/MDP check | Checks whether a finite buffer is enough to prove the modeled next step is determined. | Produces certificates, SMT-LIB queries, and reduced specs for later fitting. |
| Reduced feedforward training | Derives one policy size from each run-local reduced spec and trains it. | Boolean actions use bundled handmade NumPy PPO. Real-valued actions use bundled continuous MLP PPO. |

Full discrete training settings:

| setting | value |
|---|---:|
| PPO training episodes | `2000` |
| Episodes per PPO update | `100` |
| Eval/checkpoint interval | `100` episodes |
| Eval episodes per checkpoint | `100` |
| Final test episodes | `200` |
| Oracle samples | `2000` |
| Oracle epochs | `100` |
| Hidden size | Maximum of distinct SysML comparison boundaries and controller outputs |

## SysML Input Rules

Each file supplies its own package name and root part instance. It must contain
exactly one `#Neural` action, exactly one `#NeuralRequirement`, and exactly one
neural input marked `#Completion`. Every `#ScenarioInput` must have lower and
upper bounds in a `#ScenarioConstraint`. Process updates, flow values, and flow
merges must be written in the SysML file. Missing or ambiguous information
causes that run to stop instead of using information from another model or an
earlier run.

## Environment

Create a Python environment and install the tested dependency versions:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
bash run_fitting_sequence.sh
```

The dependency file installs the CPU build of PyTorch used by the default run.

If you already have an environment, pass its Python interpreter:

```bash
PYTHON_BIN=python bash run_fitting_sequence.sh
```

The runner defaults to `python3`.

## Overleaf Archive

Create a clean source archive with:

```bash
bash make_overleaf_archive.sh
```

This writes `../fitter_artifact_overleaf.zip`. The archive contains the runner,
bundled source and models, documentation, and pinned dependencies. It excludes
Git data, the local Python environment, generated outputs, and Python caches.
Running the artifact after extraction regenerates `outputs/latest/`.
