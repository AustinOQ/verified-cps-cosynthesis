# Controller Fitting Sequence Artifact

This is a compact, self-contained artifact for the `architecture-fit` work. It
is intended to be branch/upload friendly: one runner, one bundled code/model
tree, one output directory, and one human-readable report that demonstrates the
sequence of simplified controller fitting/training methods developed in this
subproject.

The artifact uses local copies under `bundle/`. A run reads those bundled files
and writes generated results to `outputs/latest/`.

## Run

From this directory:

```bash
bash run_fitting_sequence.sh
```

This regenerates `outputs/latest/`. By default, Stage 4 runs the full reduced
training sweep. It can take substantial time because it trains every hidden
dimension for every model.

For a quick wiring check:

```bash
bash run_fitting_sequence.sh --smoke-training
```

## What It Demonstrates

The artifact asks whether a SysML model can be controlled by a simple
non-recurrent controller instead of a larger recurrent learner.

The sequence is:

```text
1. Affine/rule fit from NeuralRequirements
2. Memoryless controller check
3. Provable Markov/MDP controller check
4. Reduced feedforward training from the run-local certified specs
```

The checks are ordered from cheapest to strongest. The final stage trains small
non-recurrent policies from the certified architecture specs generated in the
same run.

## Plain Language

- A SysML `NeuralRequirement` is the part of the model that says which
  controller outputs are safe or required for the current observation.
- The affine/rule stage asks if that requirement already gives a direct
  controller. For the cruise model this is just a few speed and distance
  inequalities.
- The memoryless stage asks if a finite history buffer is enough for the
  current controller decision. This is useful when the goal is to remove a GRU
  or other recurrent learner.
- The Markov/MDP stage asks a stronger question. It checks whether the buffer is
  enough to make the next step of the modeled process determined. This stage
  generates proof obligations from the bundled SysML files. It calls Z3 during
  the run. It saves certificates, reduced specs, SMT-LIB queries, and proof or
  counterexample transcripts under `outputs/latest/03_markov_mdp/`.
- The reduced training stage reads the specs generated by the current run. It
  sweeps hidden dimensions `2, 4, 8, 16, 32, 64`, trains feedforward policies,
  selects the smallest good model, and saves weights under
  `outputs/latest/04_reduced_training/`.
- The exact shield is the program-based safety logic from the SysML
  requirement.

## What Gets Fitted

| stage | what the checker does | fitting status in this artifact |
|---|---|---|
| Affine/rule fit | Checks whether the requirement directly gives a controller. | This is analytical. It has `0` learned parameters. Thermostat, cruise, and mixing are rerun fresh from the bundled SysML files. |
| Memoryless controller check | Checks whether a finite buffer is enough for the current decision. | Produces buffer evidence for later feedforward fitting. |
| Provable Markov/MDP check | Checks whether a finite buffer is enough to prove the modeled next step is determined. | Produces certificates, SMT-LIB queries, and reduced specs for later fitting. |
| Reduced feedforward training | Trains small policies from the run-local reduced specs and selects the smallest good model. | Discrete models use bundled handmade NumPy PPO. Continuous cruise uses bundled continuous MLP PPO. Training is CPU-only. |

Full discrete training settings:

| setting | value |
|---|---:|
| PPO training episodes | `2000` |
| Episodes per PPO update | `100` |
| Eval/checkpoint interval | `100` episodes |
| Eval episodes per checkpoint | `100` |
| Final test episodes | `200` |
| Oracle samples | `2000` |
| Oracle epochs | `100` |
| Hidden dims | `2, 4, 8, 16, 32, 64` |

## Limitations

This artifact demonstrates the fitting sequence on four bundled SysML models.
The memoryless stage supports a simple current-decision controller, while the
Markov/MDP stage checks the stronger next-step property. The program shield or
continuous projection remains the safety authority during training and
evaluation.

## Environment

Use any Python environment with the required packages installed:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install numpy z3-solver torch
bash run_fitting_sequence.sh
```

If you already have an environment, pass its Python interpreter:

```bash
PYTHON_BIN=python bash run_fitting_sequence.sh
```

The runner defaults to `python3`.
